# Mod Hub: документация для разработчиков

Этот документ объясняет, как устроен Mod Hub изнутри: из каких частей он состоит, куда и как пишет файлы, как устанавливает и откатывает моды и почему сделано именно так. Он нужен тем, кто хочет изучить код, проверить, что программа делает с игрой, или внести изменения.

Исходный код: папка `src`, тесты: `tests`, нативные компоненты: `native`. Этот же текст лежит в репозитории в `docs/developer`.

## Главные принципы

- **Оригинальные файлы Rockstar не изменяются.** Всё, что касается RPF-архивов и `update\`, пишется в копии в папке `mods\` (как в OpenIV). Защищённые файлы и папки игры перечислены в `GameInstall` и не могут быть перезаписаны или удалены.
- **Каждое изменение игры — транзакция.** Сначала план, потом подготовка копий, потом журнал, потом замена файлов по одному с проверкой хешей. Сбой или выключение компьютера посреди установки откатываются при следующем запуске.
- **Любую установку можно отменить.** Перед заменой файла его прежнее содержимое сохраняется: в служебной папке у игры и, если включено, в библиотеке резервных копий.
- **Ключи игры не распространяются.** Ключи расшифровки RPF ищутся в exe вашей копии игры и хранятся только у вас.
- **Программа портативная.** Всё своё она хранит в собственной папке; удалить папку — значит удалить программу.
- **Окно не пишет в папку игры само.** Все изменения игры выполняет консольная утилита `gmm.exe`; при необходимости она перезапускает себя с правами администратора (UAC).

## Проекты

- `GTAModManager.Core` — вся логика: формат RPF7, ключи, интерпретатор OIV, анализ архивов модов, транзакции, резервные копии, хоткеи, каталог рекомендаций, NaturalVision, Add-On PED, локализация. Не зависит от WPF.
- `GTAModManager.Cli` — утилита `gmm.exe`. Выполняет все операции, которые меняют игру. Окно вызывает её как отдельный процесс и читает её вывод.
- `GTAModManager.App` — приложение WPF (`ModHub.exe`): интерфейс, встроенный браузер (WebView2), очереди установки.
- `GTAModManager.Probe` — вспомогательная утилита для исследования архивов при разработке.
- `tests/GTAModManager.Core.Tests` — тесты xUnit для Core (несколько сотен, включая транзакции, RPF, OIV, откат, миграции).
- `tests/GTAModManager.Localization.UiHarness` — проверка того, что интерфейс корректно отображается на всех языках.
- `native/GMMPedSelector` — собственный ASI-плагин меню выбора персонажей для Legacy.
- `native/ModHubLauncher` — маленький запускатор `Mod Hub.exe` в корне папки программы, который открывает `Program\ModHub.exe`.

## Где Mod Hub хранит данные

Все пути программы собраны в одном классе: `Core/AppPaths.cs`. Писать куда-то ещё в обход него нельзя — это проверяет тест `AppPathsTests`.

```
Mod Hub by VirtuOzZ\
  Mod Hub.exe      запускатор
  Settings.json    настройки
  Languages\       пользовательские переводы
  Program\         ModHub.exe, gmm.exe, .NET и библиотеки
  Data\
    Game keys\     кэш ключей из exe игры и magic.dat
    Browser\       профиль встроенного браузера
    Downloads\     архивы, скачанные во встроенном браузере
    Cache\         данные, которые можно пересоздать (страницы модов, превью)
    Library\       записи об установленных модах и выборах пользователя
    Logs\          отчёты о непредвиденных ошибках (crash-*.txt, последние 20)
    Temp\          временные файлы; очищается при выходе
```

Рядом с `Program\ModHub.exe` лежит маркер `ModHub.portable` со строкой `root=..`: он говорит, что папка программы на уровень выше. Без маркера (сборка разработчика) папкой программы считается папка с exe. Если в папку программы нельзя писать (например, Program Files), данные идут в «Документы\ModHub».

Временные файлы: при запуске `ModHub.exe` и `gmm.exe` переменные `TEMP`/`TMP` перенаправляются в `Data\Temp`, поэтому и дочерние процессы не пишут в системный `%TEMP%`.

Кроме папки программы Mod Hub пишет только:

- **в папку игры** — сами моды, загрузчики и ASI-плагины;
- **в служебную папку на диске игры** `X:\ModHub\Legacy` или `X:\ModHub\Enhanced` (`GameInstall.WorkDir`): журналы транзакций (`journals`), подготовленные копии (`tx`, `prep`), выключенные моды (`disabled-mods`), убранное при возврате к чистой игре (`vanilla-restore`), кэш хоткеев (`keybinds`). Папка обязана быть на том же томе, что и игра: тогда установка и откат — это мгновенное переименование, а не копирование гигабайтов;
- **в папку резервных копий**, которую выбирает пользователь (по умолчанию `X:\ModHub\Backups`);
- **в реестр** `HKCU\Software\Classes` — только если пользователь сам включил открытие `.oiv` двойным щелчком (`App/FileAssociation.cs`).

«Документы\Rockstar Games» только читаются: журнал лаунчера (был ли запуск, выключен ли BattlEye) и папка `UserMods`.

## Поиск игры

`GameDetector` читает реестр и манифесты Rockstar Games Launcher, Steam и Epic Games — только чтение. Версия определяется по exe: `GTA5_Enhanced.exe` — Enhanced, `GTA5.exe` — Legacy. Путь можно указать и вручную.

## Ключи и архивы RPF

- `Crypto/Gta5Keys` ищет ключи расшифровки в exe игры по SHA-1-хешам (как CodeWalker; хеши — в `Gta5KeyHashes.cs`). Найденные ключи кэшируются в `Data\Game keys` по размеру и времени изменения exe, чтобы не читать 50 МБ при каждом запуске.
- `Crypto/MagicDat` — файл таблиц из открытого проекта CodeWalker. Если его нет, он скачивается из официального репозитория и проверяется по хешу. Без exe игры он бесполезен.
- `Rpf/Rpf7Archive` читает RPF7, `Rpf/Rpf7Writer` пишет. Копии архивов в `mods\` записываются с незашифрованным оглавлением, как это делает OpenIV. Исходный архив никогда не меняется.

## Установка модов

1. **Анализ** (`Mods/ModAnalyzer`, `Mods/ModArchive`). Архив (ZIP, RAR, 7Z) или OIV-пакет разбирается: что это — add-on DLC, ASI-плагин, скрипты, замена файлов, OIV внутри архива, варианты «выберите одно» (`Instructions/Variants`). README автора используется как подсказка, но не как источник команд.
2. **План.** Для OIV `Oiv/OivInstaller` переводит команды пакета в список изменений файлов, ничего не трогая в игре. Изменения внутри архивов готовятся в памяти (`Oiv/ArchiveSession`): для каждого файла запоминается прежнее содержимое — это нужно для точечного отката. Правки текста и XML (`Oiv/TextEdits`) сохраняют BOM и переводы строк.
3. **Правила путей** (`GameInstall`): всё, что относится к RPF и `update\`, идёт в `mods\`; ASI, `scripts\` и прочие свободные файлы — в корень игры. Оригиналы защищены.
4. **Add-on DLC** регистрируется в `dlclist.xml` минимальной правкой (`Dlc/DlcList`): существующие строки не переписываются. Если установлен загрузчик onigiri от NaturalVision Enhanced, регистрация дублируется в его копию файлов (`Oiv/OnigiriOverlay`), иначе игра пакет не увидит.
5. **Транзакция** (см. ниже) применяет план.
6. **Запись** об установке попадает в журнал, в «Мои моды» и, если включены, в библиотеку резервных копий.

Очередь из нескольких модов одобряется одним запросом UAC (`Installation/BatchChannel`, `DropBatch`).

## Транзакции

`Transactions/FileTransactionEngine` применяет набор изменений в пределах одной папки (корень игры):

1. Проверки: права на запись, свободное место, ожидаемые хеши файлов «до».
2. Подготовка: новые файлы копируются в `WorkDir\tx\<id>` — на том же томе, поэтому дальше их можно перемещать мгновенно.
3. Журнал с упреждающей записью (`WorkDir\journals\<id>.json`): перед изменением каждого файла в журнал записывается, что сейчас произойдёт.
4. Замена по одному файлу: старый файл откладывается в резервную копию, новый ставится на место, проверяется хеш.
5. Сбой на любом шаге или аварийное завершение процесса — откат по журналу при следующем запуске (`Recover`). Если состояние неоднозначное (файл изменён кем-то ещё), транзакция помечается `NeedsIntervention`, и программа ничего не перезаписывает вслепую.

Отмена установки (`Undo`) сначала проверяет, что установленные файлы не менялись после установки; иначе ничего не трогает. «Удалить» на карточке мода (`Inventory/ModRemoval`) отменяет все установки этого мода, от новой к старой, и возвращает даже записи внутри общих архивов вроде `update.rpf`, не задевая чужие.

Межпроцессная блокировка на каждую папку игры (`Game/GameOperationGate`) не даёт двум операциям менять игру одновременно.

## Резервные копии

`Library/BackupLibrary` — необязательная библиотека в выбранной пользователем папке. В ней хранятся только изменённые файлы (целиком и отдельные файлы внутри RPF), по SHA-256: одинаковое содержимое хранится один раз. Есть лимит размера; старые копии автоматически не удаляются — освобождается только то, на что не ссылается ни одна действующая установка. `Library/VanillaOracle` определяет, является ли прежнее содержимое файла оригиналом игры, сравнивая его с тем же файлом в неизменённом архиве.

В папке резервных копий также лежит `Mod Hub settings` (`Library/SettingsMirror`): копия `Settings.json`, `Data\Library` и переводов. Она обновляется при каждом сохранении настроек и при выходе. Если после переустановки выбрать эту же папку, программа предложит восстановить настройки.

## Включение и выключение модов, чистая игра

- `Game/ModModeService` выключает моды без удаления: загрузчики (Script Hook V, ScriptHookVDotNet, загрузчики ASI и папки mods) переименовываются на месте в `*.gmm-off`, включение возвращает имена.
- `Game/VanillaRestore` убирает из папки игры всё, что не поставлялось Rockstar: `mods\`, ASI/DLL/скрипты в корне, архивы модов (незашифрованные) в `update\` и `x64\`, выключенные загрузчики. Убранное либо удаляется, либо переносится в `WorkDir\vanilla-restore`. Оригинальные файлы не трогаются.
- `Game/GamePermissions` проверяет реальной попыткой записи, может ли пользователь писать в папку игры, и при необходимости исправляет права в отдельном процессе с UAC.
- `Game/GameReadiness` только читает журнал лаунчера: запускалась ли игра хотя бы раз и выключен ли BattlEye.
- `Game/GameLauncher` запускает игру через официальный лаунчер, а не напрямую через exe.

## Хоткеи модов

`Keybinds/KeybindScanner` ищет назначения клавиш только в разрешённых местах: корень игры (`*.ini`, `modhub.json`), `scripts\` и `plugins\` (до 4 уровней). Папка `mods\`, RPF-архивы и файлы игры не читаются. Парсеры INI, JSON и XML распознают клавиши строго; сомнительные значения требуют подтверждения. Изменение (`KeybindEditor`) пишется как обычная транзакция с точечной правкой строки, сохраняющей форматирование; JSON и XML пока только читаются. `KeybindConflictAnalyzer` ищет пересечения, в том числе со стандартными клавишами игры.

Отключить можно любую клавишу (`KeyNotation.FormatDisableToken`): там, где известен свой «пустой» формат мода, пишется он (`None`, `0,0,0,0`, код `0`), иначе — F24, которой нет на клавиатурах; такое значение читается как «отключено». `Keybinds/KeybindSwitches` знает выключатели всех клавиш мода, описанные его автором (Simple Trainer: `KeyBindingsDisabled`). `Keybinds/Gamepad` находит кнопки геймпада: в INI моды хранят номер управления GTA (`GamepadControls`), а не саму кнопку; экран показывает её по раскладке Xbox или PlayStation (`AppSettings.GamepadLayout`).

## Рекомендации и загрузки

- Каталог рекомендаций — `Discover/catalog.json`, обложки — в `App/Discover/Assets`. Динамические данные (рейтинг, загрузки, автор) читаются со страниц GTA5-Mods (`Discover/Gta5ModsPageParser`): только то, что сайт публикует для машин (schema.org JSON-LD, og-теги, счётчики). Комментарии пользователей не читаются.
- Скачивание (`Discover/Gta5ModsDownloads`) повторяет путь обычного посетителя: страница мода → кнопка Download → файл с `files.gta5-mods.com`, с правильным Referer, чтобы загрузка засчиталась автору. Принимаются только https и только архивы модов.
- Встроенный браузер (WebView2) открывает только https; скачанные в нём архивы попадают в `Data\Downloads`. Папку «Загрузки» пользователя программа не перечисляет и не чистит.
- База для моддинга (`Base/*`): загрузчик папки `mods` RageOpenV (авторы martonp96 и Chiheb-Bacha) Mod Hub не распространяет — он скачивается из официального релиза авторов на GitHub, закреплённого на проверенной версии и сверенного по SHA-256 (`Base/RageOpenVDownloads.cs`). Script Hook V скачивается со страницы dev-c.com тем же способом, что и при клике посетителя; ScriptHookVDotNet — из релизов GitHub.
- «Поддержите автора» (`Discover/AuthorThanks`) один раз предлагает открыть страницу мода после того, как мод попробовали в игре. Сама программа ничего не отправляет.

## NaturalVision и LCPP

`NaturalVision/NveService` ставит выбранные компоненты NaturalVision Enhanced из архива, который пользователь скачал сам, и учитывает загрузчик onigiri. LCPP-компоненты ставятся как отдельные транзакции одной установки, поэтому откатываются по частям в правильном порядке.

Загрузчик onigiri (NaturalVision Enhanced) не читает `mods\`: он подставляет свою папку вместо устройств игры (`onigiri\common` = `common:/`, `onigiri\platform` = `platform:/`, то есть `update.rpfd` и архивы `x64*.rpf`, `onigiri\dlcpacks` = `dlcpacks:/`). Поэтому при onigiri `GameInstall.CheckModLoader` считает загрузчиком его, а установка NVE той же транзакцией убирает OpenRPF/RageOpenV (`OivInstaller.PrepareLoaderHandOff`). `Oiv/OnigiriLayer` после каждой установки и отмены пересчитывает свободные копии всего, что моды поменяли в архивах `mods\` (файл или первый вложенный архив целиком), и ведёт их список в `ModHubState\onigiri-layer.json`. Такие файлы помечены в записи как производные (`FileBackup.Derived`): откат их не восстанавливает, а пересчитывает. Чужие файлы в `onigiri\` (в том числе файлы самого NVE) не перезаписываются — в плане появляется предупреждение. Add-on DLC, dlclist и пулы по-прежнему ведёт `Oiv/ModCompatibility`.

Лимиты (`Installation/LimitSetup`): либо классический набор (HeapAdjuster, расширители Packfile/Modkit/StaticBounds и gameconfig; с NVE хватает его gameconfig в onigiri), либо Resource Extensions (`ResourceExtensions.asi`), который заменяет всё это и не поддерживает свой gameconfig. При Resource Extensions расширители не предлагаются, а смешанный или двойной набор показывается жёлтой плашкой.

## Add-On PED (только Legacy)

`Peds/*` готовит обычную OIV-транзакцию: пакет с раскладкой классического Ped Selector (`pedselector`), список персонажей хранится внутри пакета (`peds.meta`). Собственный ASI-селектор (`native/GMMPedSelector`) необязателен; сторонние селекторы только обнаруживаются. Сохранённые образы персонажей селектор пишет в папку игры `GMMPedSelector\looks.txt`; лог он не ведёт.

`Peds/PedSelectorImport` возвращает персонажей из сохранённого пака Ped Selector: `peds.rpf` из `pedselector\dlc.rpf` распаковывается в папку и идёт через обычную очередь; регистрации пака не переносятся, пол выбирается заново.

## Локализация

Тексты — в JSON-пакетах `Core/Localization/Languages` (ru — исходный язык, en, uk); официальные пакеты встроены в сборку. При первом запуске выбран английский. Пользовательские пакеты кладутся в папку `Languages` и подхватываются без перезапуска; недостающие строки берутся из официального пакета того же языка, затем из русского. Формат и правила — в `docs/localization.md`. Тест `OfficialLanguageCoverageTests` требует, чтобы en и uk содержали все ключи.

## Утилита gmm.exe

`gmm` без аргументов печатает список команд. Основные: `info`, `oiv`, `mod`, `history`, `undo`, `mods-status`, `mods-disable`, `mods-enable`, `vanilla-restore`, `keybinds`, `keybind-set`, `peds-*`, `base-install`, `backup-setup`, `backup-info`. Команды, меняющие игру, перезапускают `gmm` с UAC; вывод возвращается через лог-файл во временной папке программы (`Processes/LiveLogRelay`). Окно программы вызывает те же команды.

## Удаление программы

Настройки → «Удалить Mod Hub…» (`App/MainWindow.Uninstall.cs`): по выбору возвращает игры к чистому состоянию или убирает только собственные компоненты, оставляет или удаляет резервные копии вместе со служебной папкой, снимает ассоциацию `.oiv`, а папку программы удаляет после выхода командой `cmd.exe` (без временных скриптов).

## Сборка и проверка

Нужно: Windows 10/11 x64, .NET SDK 10 (версия в `global.json`). Для нативных компонентов — Visual Studio с C++ и CMake; для сборки самого приложения они не нужны, готовые бинарники лежат в репозитории.

```
dotnet build GTAModManager.slnx -c Release
dotnet test GTAModManager.slnx
.\scripts\publish-portable.ps1        # тесты → публикация → build\ModHub-portable.zip
.\scripts\check-portable-writes.ps1   # готовая сборка не пишет вне своей папки
.\scripts\build-addonpeds.ps1         # пересборка GMMPedSelector.asi
```

## Правила для изменений

- Комментарии в коде — на английском, тексты интерфейса — только через локализацию (`L.T("key")`), с переводом на en и uk.
- Новые файлы программы — только через `AppPaths`; служебные данные игры — только в `GameInstall.WorkDir`.
- Любое изменение папки игры — только через `FileTransactionEngine` и `gmm.exe`, никогда напрямую из окна.
- Оригинальные файлы Rockstar не перезаписываются и не удаляются.
- Новая логика — с тестами в `GTAModManager.Core.Tests`.
